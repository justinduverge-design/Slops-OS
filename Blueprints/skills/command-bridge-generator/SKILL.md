# Command Bridge Generator

## Purpose

Use this skill to expose approved SLOPS Blueprint skills and approved SLOPS agents to Claude and Codex through their native discovery folders.

The bridge is a shim layer. `Blueprints` remains the canonical source of truth. Generated files should point back to canonical SLOPS files instead of becoming independent doctrine.

## Skill Identity

- **Skill name:** `command-bridge-generator`
- **Primary user:** Justin
- **Primary agents:** Claude for review and routing; Codex for file generation when instructed.
- **DBS layer:** `Blueprints\skills`
- **Skill type:** simple skill
- **Status:** active

## When to Use

Use this skill when Justin asks to:

- Make SLOPS skills available as Claude slash commands.
- Make SLOPS skills available to Codex as repo skills.
- Generate `.claude`, `.agents`, or `.codex` shim files.
- Sync approved Blueprint skills into local tool-discovery folders.
- Generate Claude or Codex agent shims from approved `AGENT_INDEX.md` rows.
- Preview which skills or agents would become invocable before writing bridge files.

Do not use this skill when:

- The target skill or agent is not approved in the routing/index files.
- The source is imported, archived, candidate-only, reference-only, or do-not-activate.
- Justin asks to create a new skill; use `slops-skill-author`.
- Justin asks to create or promote an agent; use `slops-agent-author`, `agent-wrapper-generator`, or `agent-index-diff-builder`.
- The task requires secrets, production, auth, payments, databases, deployment, or infrastructure changes.

## Required Inputs

Minimum inputs:

- Bridge target:
  - `claude-skills`
  - `codex-skills`
  - `claude-agents`
  - `codex-agents`
  - `all`
- Mode:
  - `preview`
  - `write`
- Current routing files:
  - `Blueprints\skills\SKILL_ROUTING.md`
  - `Blueprints\agents\AGENT_INDEX.md`

If Justin does not specify a mode, default to `preview`.

## Canonical Sources

Read:

```text
Blueprints\skills\SKILL_ROUTING.md
Blueprints\agents\AGENT_INDEX.md
Blueprints\tools\tool-permissions.md
```

Read skill bodies only for rows approved for bridge generation:

```text
Blueprints\skills\<skill-name>\SKILL.md
```

Read agent bodies only for rows approved for bridge generation:

```text
Blueprints\agents\<division>\<agent>.md
```

## Generated Target Folders

Claude skill shims:

```text
.claude\skills\<skill-name>\SKILL.md
```

Codex skill shims:

```text
.agents\skills\<skill-name>\SKILL.md
```

Claude agent shims:

```text
.claude\agents\<agent-name>.md
```

Codex agent shims:

```text
.codex\agents\<agent-name>.toml
```

Do not write into user-global folders such as `~\.claude`, `~\.codex`, or `~\.agents` unless Justin explicitly asks for user-wide installation.

## Approval Rules

### Skills

A skill may receive a command bridge only when:

- It appears in `Blueprints\skills\SKILL_ROUTING.md`.
- It appears as `active` in the Active SLOPS Skills section of `Blueprints\agents\AGENT_INDEX.md`.
- Its canonical `Blueprints\skills\<skill-name>\SKILL.md` exists.
- It is not `_template`, imported, archived, or reference-only.

### Agents

An agent may receive a command bridge only when:

- It appears in `Blueprints\agents\AGENT_INDEX.md`.
- Its status is `active`.
- Its path points to a SLOPS-authored agent file, not `_imported`.
- Its tool tier cap and approval gates are explicit.
- Justin has not marked it restricted, candidate, reference-only, or do-not-activate.

Candidate wrapper files under `Blueprints\agents\<division>` are not enough. Division folders do not grant authority.

## Read-First Procedure

Use least privilege.

1. Read Justin's request and identify mode: `preview` or `write`.
2. Read `SKILL_ROUTING.md`.
3. Read `AGENT_INDEX.md`.
4. Read `tool-permissions.md` if generating agent shims.
5. Build an approved list from the routing/index files.
6. Read only the canonical files for approved rows.
7. Do not read `_imported`, `Archive`, `.env`, secrets, production configs, app source, or old project copies.

## Process Recipe

1. Build a candidate bridge inventory:
   - approved skills
   - approved Claude agents
   - approved Codex agents
2. Remove anything not approved by both the relevant routing/index row and the source file existing on disk.
3. Detect collisions:
   - duplicate skill names
   - skill name matching an existing command
   - agent name matching another agent
   - a target file that already exists and was not generated by this bridge
4. In `preview` mode, write no files. Report:
   - files that would be created
   - files that would be skipped
   - collisions
   - approval gaps
5. In `write` mode, generate only approved shims.
6. Preserve existing non-bridge files. Do not overwrite unless the file is clearly bridge-generated or Justin explicitly approves replacement.
7. Report all created, updated, skipped, and blocked files.

## Skill Shim Pattern

Use this pattern for `.claude\skills\<skill-name>\SKILL.md` and `.agents\skills\<skill-name>\SKILL.md`:

```markdown
---
name: <skill-name>
description: Bridge shim for the canonical SLOPS skill at Blueprints\skills\<skill-name>\SKILL.md. Use when Justin invokes /<skill-name> or the task matches the canonical skill.
---

# <Skill Name> Bridge

This is a generated bridge shim.

Canonical source:

```text
Blueprints\skills\<skill-name>\SKILL.md
```

Before acting, read the canonical source file and follow it.

Do not treat this shim as independent authority. If this shim conflicts with the canonical source, the canonical source wins.
```

Do not copy long skill bodies into shims unless Justin explicitly asks for fully duplicated portable commands.

## Claude Agent Shim Pattern

Use this pattern for `.claude\agents\<agent-name>.md`:

```markdown
---
name: <agent-name>
description: <one-line approved purpose from AGENT_INDEX.md>
tools: Read, Glob, Grep
model: inherit
---

# <Agent Name>

This is a generated SLOPS agent bridge.

Canonical source:

```text
<canonical agent path>
```

Follow the canonical agent file, `Blueprints\agents\AGENT_INDEX.md`, and `Blueprints\tools\tool-permissions.md`.

Do not exceed the canonical tool tier cap. Escalate anything outside the approved role.
```

Only include write-capable tools when the active agent row explicitly allows them and Justin approves the bridge.

## Codex Agent Shim Pattern

Use this pattern for `.codex\agents\<agent-name>.toml`:

```toml
name = "<agent-name>"
description = "<one-line approved purpose from AGENT_INDEX.md>"
model = "inherit"

instructions = """
This is a generated SLOPS agent bridge.

Canonical source:
<canonical agent path>

Follow the canonical agent file, Blueprints\\agents\\AGENT_INDEX.md, and Blueprints\\tools\\tool-permissions.md.

Do not exceed the canonical tool tier cap. Escalate anything outside the approved role.
"""
```

If the Codex runtime requires a different TOML shape, stop and report the needed adjustment before writing agent shims.

## Output Contract

In `preview` mode, produce:

- Source routing files read.
- Approved skills found.
- Approved agents found.
- Proposed `.claude`, `.agents`, and `.codex` shim paths.
- Skipped items and reasons.
- Collision or overwrite risks.
- Next safe command to run in write mode.

In `write` mode, produce:

- Files created.
- Files updated.
- Files skipped.
- Files blocked.
- Source files used.
- Any manual restart/reload notes for Claude or Codex.

## DBS Routing

- Canonical skills stay in `Blueprints\skills`.
- Canonical agents stay in `Blueprints\agents`.
- Generated Claude shims go to `.claude`.
- Generated Codex skill shims go to `.agents`.
- Generated Codex agent shims go to `.codex`.
- Bridge reviews or previews may be written to `Direction\reviews` when requested.

## RBAC Boundaries

This skill may generate command bridge files only from approved authority rows.

It may not:

- Promote candidate agents.
- Expose imported agents.
- Convert reference-only material into commands.
- Grant tool permissions beyond `AGENT_INDEX.md` and `tool-permissions.md`.
- Write user-global shims without explicit approval.
- Read or write secrets, `.env`, cookies, auth, payments, database, production, deployment, DNS, SSL, VPS, or external account files.
- Delete existing bridge files.
- Overwrite non-bridge files without explicit approval.

Escalate to Justin before any write that changes tool permissions, enables external-system mutation, or exposes an agent with Tier 3 or higher capability.

## Failure Modes

Watch for:

- Treating all Blueprint skills as active when routing/index does not approve them.
- Exposing candidate agent wrappers as commands.
- Copying stale skill bodies into shims and creating divergent doctrine.
- Overwriting manually authored Claude or Codex files.
- Confusing Claude skills with Claude agents.
- Confusing Codex skills with Codex agents.
- Installing globally when the request only asked for repo-level bridge files.
- Ignoring runtime reload/restart requirements.
