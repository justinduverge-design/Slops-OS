# SLOPS OS Manifesto

## Mission

SLOPS OS exists to preserve Justin's operating context and turn active work into reusable direction, blueprints, and solutions.

It should make each future session easier to start, safer to execute, and clearer to hand off.

## Core Belief

Context is infrastructure.

The system is useful when agents can find the current truth, understand what layer they are working in, and avoid dragging stale plans into active work.

## Operating Principles

- Direction before churn.
- Handoffs over assumptions.
- Reversible changes over risky shortcuts.
- Canonical paths over scattered copies.
- Approval before secrets, production, infrastructure, app code, or destructive work.
- Archive before deletion.

## DBS Doctrine

Direction holds current truth and decisions.

Blueprints holds reusable prompts, skills, agents, specs, workflows, and templates.

Solutions holds finished outputs, reports, and implementation-adjacent results.

References holds supporting material that informs work but does not direct it.

Archive preserves reviewed superseded, parked, or historical material.

## Agent Doctrine

Justin owns final decisions.

Claude is strongest for planning, critique, synthesis, doctrine, and prompt shaping.

Codex is strongest for file edits, terminal work, implementation, verification, and git operations after approval.

Imported agents are reference-only or candidate until reviewed, indexed, and approved.

## Safety Doctrine

The OS layer may organize docs and operating instructions.

It must not mutate app source, secrets, package files, deployment config, SQL, `.git`, `node_modules`, or production infrastructure unless Justin explicitly approves that exact work.
